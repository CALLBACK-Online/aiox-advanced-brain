# Task, skill, workflow ou squad

> Resultado: selecionar a menor unidade AIOX que resolve o problema.

## Objetivo

Comparar as unidades de execução por granularidade, reuso e coordenação.

## Contexto

Complexidade visível costuma parecer competência. No AIOX, o critério é proporcionalidade: uma task clara não precisa virar squad; um processo com vários handoffs não deve ser comprimido num prompt improvisado.

## As unidades

- **Agent:** responsável especializado que interpreta contexto e opera assets.
- **Task:** procedimento delimitado com entrada, passos e saída.
- **Skill:** capacidade empacotada para uma superfície de agent, normalmente com instruções e recursos próprios.
- **Workflow:** sequência de etapas, estados ou handoffs para um resultado maior.
- **Squad:** pacote de domínio com agents, tasks, templates, dados ou workflows coordenados.

O agent responde **quem**. As demais unidades respondem **como e em qual escala**.

## Onde as 67 skills do acervo se encaixam

Este vault distribui dezenas de skills. Elas **não** são todas “core de story”. Três famílias:

| Família | Exemplos | Onde estudar “como usar” |
|---------|----------|---------------------------|
| **Core runtime** (orbitais + SDC) | `aiox-dev`, `validate-story-draft`, `full-sdc` | **Este curso** + [core-skills-runtime.md](../../references/core-skills-runtime.md) |
| **Entrada de squad** (24) | `research`, `design-system`, `sales` | Aula 1:1 em `cursos/AIOX-Advanced-Squads/aulas/` + `SKILL.md` com “Quando usar” |
| **Portable / vault / util** | `teach`, `tech-search`, `slide-creator`, `impeccable` | `cursos/MAPA-SKILLS.md` + `SKILL.md` |

### Anti-duplicação rápida

- **`slide-creator`** = deck standalone (portable). **`slides-creator`** = squad + aula 17.
- **`tech-search`** vs **`tech-research`**: search = leve self-contained; research = pipeline mais fundo / multi-fonte — se a missão for o squad de research, use a **aula 02** do curso Squads.
- Skill de squad **não** substitui o mapa de decisão: se a dor for ambígua, use `aiox-squads` primeiro.

Mapa completo e manutenção do acervo: arquivo `cursos/MAPA-SKILLS.md` (fora desta pasta de curso).

## Decisão por menor mecanismo

Use uma **task** quando:

- há um objetivo único;
- os passos são conhecidos;
- uma pessoa ou agent consegue fechar o resultado;
- o output é um artefato claro.

Use uma **skill** quando:

- a capacidade precisa ser invocável e reutilizável na IDE;
- há instruções, scripts ou referências próprias;
- o escopo continua estreito.

Use um **workflow** quando:

- existe ordem ou estado entre etapas;
- um resultado alimenta o próximo;
- checkpoints ou retries importam.

Use um **squad** quando:

- o domínio exige vários especialistas;
- há vários tipos de artefato;
- a coordenação é parte essencial da solução;
- o pacote será reutilizado como unidade.

## Exemplo

Necessidade: “validar se uma story está pronta”.

- Task: checklist de validação de uma story.
- Skill: capacidade `validate` empacotada para a IDE.
- Workflow: draft → validate → develop → review → close.
- Squad: desnecessário se o objetivo é somente validar uma story.

Necessidade: “operar uma esteira editorial completa com pesquisa, escrita, revisão e distribuição”.

- Uma task isolada não representa os handoffs.
- Um workflow pode bastar se os papéis forem simples.
- Um squad faz sentido quando os especialistas e assets de domínio precisam viajar juntos.

## Erro comum

Criar um squad para parecer completo. Isso aumenta manutenção, paths, dependências e pontos de falha.

O erro oposto é esconder um pipeline multiagente dentro de uma task gigantesca. Se há estados, autoridades diferentes ou retomada, modele a coordenação.

## Prática

Classifique:

1. gerar changelog de uma release;
2. revisar uma story;
3. executar SDC completo;
4. criar e manter um design system;
5. auditar uma migração;
6. empacotar operação de vendas com pesquisa, copy e materiais.

Para cada caso, justifique por que o mecanismo imediatamente maior seria excesso.

## Recuperação sem IA

Explique em uma frase a diferença entre agent, task, skill, workflow e squad.

## Evidência

Seis necessidades classificadas com justificativa de granularidade e limites.
