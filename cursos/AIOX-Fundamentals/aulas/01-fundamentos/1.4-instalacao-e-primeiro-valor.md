# Instalação e primeiro valor

> Resultado: escolher a instalação correta, executar diagnóstico e ativar um agent.

## Objetivo

Instalar o core em projeto novo ou existente, verificar a saúde da instalação e obter um primeiro output útil.

## Contexto

O pacote atual é `@aiox-squads/core`, mas o comando `aiox-core` permanece como alias de CLI. No snapshot do curso, os pré-requisitos mínimos documentados são Node.js 18+, npm 9+ e Git.

Antes de executar, decida:

- **Greenfield:** ainda não existe projeto; use `init`.
- **Brownfield:** o projeto já existe; entre nele e use `install`.

Não faça a instalação dentro deste acervo de cursos. Use um projeto próprio ou uma pasta descartável criada para a prática.

## Passos

### 1. Verifique pré-requisitos

    node --version
    npm --version
    git --version

### 2. Escolha uma rota

Projeto novo:

    npx aiox-core@latest init meu-projeto

Projeto existente:

    cd caminho-do-projeto
    npx aiox-core@latest install

Para inspecionar uma instalação brownfield sem aplicar mudanças, o instalador documenta:

    npx aiox-core@latest install --dry-run

### 3. Rode o diagnóstico

    npx aiox-core@latest doctor

Use `doctor --fix` somente após ler o que será corrigido. Um comando de reparo é mutável; o diagnóstico simples é a primeira escolha.

### 4. Confirme a estrutura

Verifique se existem a configuração, os agents e as projeções da IDE selecionada. O instalador pode gerar superfícies diferentes para Claude Code, Codex, Gemini, Cursor, Copilot ou AntiGravity.

### 5. Ative um agent

Use a superfície que o instalador registrou no runtime atual. Em runtimes com ativação por menção, `@aiox-master` é a forma documentada; outros runtimes podem expor skill, comando ou prompt equivalente.

Após a ativação, use `*help` se esse comando estiver listado pelo próprio agent. A definição carregada é a fonte de verdade; não suponha paridade total entre IDEs.

## First-value

Instalação concluída não é first-value. O primeiro valor exige:

1. agent ativado;
2. papel apresentado;
3. contexto do projeto reconhecido;
4. comando disponível confirmado;
5. output útil, ainda que pequeno.

Exemplo seguro: pedir ao agent um resumo do estado atual e a rota recomendada para uma mudança, sem autorizar alterações.

## Erro comum

Usar `init` dentro de um projeto existente ou executar `--force` sem entender o que será sobrescrito.

Outro erro é copiar uma sintaxe de ativação de outra IDE. Sempre confirme a superfície gerada na instalação atual.

## Prática

Instale ou audite o AIOX e registre:

    tipo: greenfield | brownfield
    versão do Node:
    comando usado:
    doctor: PASS | FAIL
    runtime:
    agent ativado:
    primeiro output útil:

Se o doctor falhar, a prática termina no diagnóstico. Não esconda a falha.

## Recuperação sem IA

Explique quando usar `init`, `install`, `install --dry-run` e `doctor`.
