# Anatomia do framework

> Resultado: localizar as peças do core e explicar como elas se conectam.

## Objetivo

Identificar configuração, agents, tasks, templates, checklists e workflows sem precisar decorar a árvore inteira.

## Contexto

Uma instalação atual do AIOX coloca o core dentro do projeto. A estrutura exata pode evoluir, mas o snapshot 5.2.9 organiza os assets principais assim:

    .aiox-core/
    ├── core/             mecanismos do framework
    ├── development/
    │   ├── agents/       papéis, comandos e autoridade
    │   ├── tasks/        procedimentos executáveis
    │   └── workflows/    sequências coordenadas
    ├── product/
    │   ├── templates/    formatos de saída
    │   └── checklists/   critérios de verificação
    ├── infrastructure/   scripts e integrações
    └── core-config.yaml  configuração do projeto

O core também projeta superfícies para IDEs compatíveis. Esses arquivos gerados são meios de ativação; as definições canônicas permanecem no core.

## Como as peças se conectam

- **Configuração:** informa paths, preferências e condições do projeto.
- **Agent:** define papel, foco, limites, comandos e dependências.
- **Task:** descreve um procedimento com entrada, passos e saída.
- **Template:** padroniza o artefato produzido.
- **Checklist:** torna a revisão explícita.
- **Workflow:** coordena várias tasks ou agents em uma sequência.
- **Script:** automatiza uma operação determinística.

Fluxo típico:

    configuração
         ↓
    agent escolhe task
         ↓
    task usa template
         ↓
    checklist valida
         ↓
    workflow entrega ao próximo papel

Um arquivo não ganha autoridade só por estar no core. A definição do agent e as regras do projeto determinam quem pode fazer o quê.

## Exemplo

Para preparar uma story:

1. O Scrum Master lê o contexto e o epic.
2. Uma task de drafting orienta a elaboração.
3. Um template garante campos consistentes.
4. Um checklist verifica completude.
5. O Product Owner decide se a story está pronta.
6. O handoff aponta para desenvolvimento.

## Erro comum

Editar arquivos internos do core para “resolver rápido” um problema do projeto. Antes de tocar no framework, descubra se a mudança pertence ao código do produto, à configuração local ou a um asset de projeto.

Outro erro é decorar nomes de pastas sem entender o fluxo. O mapa útil responde “quem executa qual procedimento e que artefato prova o resultado?”.

## Prática

Em uma instalação AIOX, localize:

1. a configuração;
2. a definição do agent de desenvolvimento;
3. uma task usada por ele;
4. um template;
5. um checklist;
6. um workflow.

Não altere nada. Registre apenas path e função.

## Recuperação sem IA

Desenhe de memória a cadeia configuração → agent → task → template → checklist → handoff.

## Evidência

Um mapa com seis paths reais da instalação e uma frase sobre a função de cada um.
