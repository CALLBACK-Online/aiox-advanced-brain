# O que é AIOX

> Resultado: explicar onde o AIOX entra entre a sua intenção, a IA e o projeto.

## Objetivo

Definir AIOX como um framework de orquestração e distinguir três coisas que iniciantes costumam misturar: modelo de IA, interface e framework.

## Contexto

Um modelo de IA gera respostas. Uma interface permite conversar com esse modelo. O AIOX organiza como o trabalho acontece dentro de um projeto: qual papel assume a tarefa, quais fontes de contexto devem ser lidas, qual procedimento é executado, qual artefato é produzido e como o resultado é validado.

O core é instalado no projeto. Ele traz definições de agents, tasks, templates, checklists, workflows, configuração e guardrails. A IDE ou CLI continua sendo a superfície de interação; o modelo continua sendo o motor cognitivo. O AIOX é a camada operacional que conecta ambos ao repositório.

## Passos

1. Comece pela intenção: “quero corrigir um bug”, “quero definir um produto” ou “quero revisar uma entrega”.
2. Leia o contexto real do projeto.
3. Escolha o agent cuja responsabilidade coincide com o trabalho.
4. Execute uma task ou workflow confirmado no core.
5. Produza um artefato persistente no repositório.
6. Feche com validação e evidência.

O fluxo mental é:

    intenção → contexto → papel → procedimento → artefato → evidência

Sem essa cadeia, a interação vira uma sequência de prompts isolados. Com ela, outra pessoa ou outro agent consegue entender o estado e continuar.

## Exemplo

Pedido: “adicione recuperação de senha”.

- O modelo de IA ajuda a raciocinar e escrever.
- A IDE expõe arquivos, terminal e comandos.
- O AIOX distribui o trabalho: requisitos, arquitetura, story, implementação, QA e operação remota.
- O repositório guarda a decisão, o código e as provas.

## O que AIOX não é

- Não é um modelo de IA.
- Não é sinônimo de Claude Code, Codex, Cursor ou Gemini.
- Não é uma promessa de autonomia sem supervisão.
- Não substitui os requisitos, os testes ou a decisão humana.
- Não transforma uma tarefa ambígua em entrega correta por mágica.

## Erro comum

Tratar o AIOX como “uma coleção de prompts”. Prompts podem fazer parte da interface, mas o valor do framework está no contrato entre papéis, assets, estado, autoridade e gates.

## Prática

Classifique cada item:

1. GPT-5 ou Claude: modelo, interface ou framework?
2. Codex ou Claude Code: modelo, interface ou framework?
3. `.aiox-core/development/agents/dev.md`: modelo, interface ou framework?
4. Um arquivo de story com critérios de aceite: motor, superfície ou artefato operacional?

Depois escreva em uma frase: “O AIOX entra no meu projeto para…”.

## Recuperação sem IA

Feche a aula e explique, sem consultar: qual é a diferença entre modelo, interface, framework e repositório?
