# Projeto integrador — uma missão, três squads

[⌂ Curso](README.md) · [Rubrica](Rubrica.md) · [Avaliações](Assessments.md)

## Desafio

Escolha uma missão real e use pelo menos três squads de módulos diferentes para transformá-la em uma entrega validada. O projeto avalia a qualidade da composição, não a quantidade de agentes ativados.

Exemplos:

- Research → Advisory Board → AIOX SOP para investigar, decidir e padronizar um processo;
- Brand → Design System → Slides Creator para traduzir estratégia em uma apresentação coerente;
- Hormozi → Copy → Sales para estruturar oferta, mensagem e abordagem comercial;
- Code Anatomist → Domain Decoder → DB Sage para compreender um legado antes de alterar o modelo de dados.

## Entregáveis

1. `mission-brief.md`: problema, estado atual, público, restrições e resultado.
2. `routing-decision.md`: squads considerados, escolha, ordem e anti-escopo.
3. Um briefing específico para cada squad.
4. Artefatos intermediários e final.
5. `validation-report.md`: critérios, testes, falhas, correções e veredito.
6. `retrospective.md`: o que manter, mudar ou automatizar na próxima execução.

## Regras

- cada squad deve ter uma transformação própria e verificável;
- o output de uma etapa deve ser entrada explícita da próxima;
- maturidade e dependências devem ser declaradas antes da execução;
- efeitos externos exigem autorização registrada;
- falhas encontradas no gate devem ser corrigidas e revalidadas.

## Definição de pronto

O projeto está pronto quando outra pessoa consegue entender a missão, reproduzir a rota, localizar os artefatos, verificar os critérios e explicar por que cada squad foi necessário.
