# Quiz M11 — Produtivização

Eu respondo sem consultar as aulas. Depois abro o gabarito, explico cada erro com minhas palavras e volto à evidência do módulo. Minha referência de domínio é 80%.

## Questões

### 1. Service-as-Software parte de:

- A. SaaS genérico sem serviço validado
- B. Só landing page
- C. Serviço que já vende, produtizando o gargalo repetível
- D. Só paper acadêmico

### 2. A provocação 10/90 (produto/distribuição) alerta para:

- A. IA barateou build — o jogo migra para distribuição
- B. Construir 90% e distribuir 10% para sempre
- C. Ignorar produto
- D. Só ads pagos

### 3. Vender pela dor e ROI significa:

- A. Abrir o pitch com lista de 12 agentes
- B. Só jargão de modelo
- C. Prometer 100x sem premissa
- D. Dor atual (custo) → mecanismo → delta mensurável → prova

### 4. Harness de execução existe quando:

- A. Só você usa o chat do Claude Code
- B. Cliente/SLA/24-7 exige runtime fora da IDE
- C. Nunca
- D. Só para print de marketing

### 5. Você tem uma automação tecnicamente forte, mas ninguém compra. Qual é o próximo experimento?

- A. Adicionar funcionalidades para parecer mais completa
- B. Transformar imediatamente em SaaS self-service
- C. Escolher uma dor, medir a baseline, prometer um resultado e testar oferta e distribuição
- D. Reduzir o preço sem conversar com clientes

<details>
<summary>Gabarito comentado</summary>

**1. C** — Wedge do serviço real.

**2. A** — Audite ratio real de tempo.

**3. D** — DOR vende; stack é meio.

**4. B** — Demo de IDE ≠ produto.

**5. C** — Produtivização começa no problema e no mecanismo de valor; produto sem distribuição continua invisível.

</details>

## Transferência

Eu produzo esta evidência no meu projeto: One-pager com baseline, promessa mensurável, escopo, harness, caminho de monetização e teste de distribuição.
