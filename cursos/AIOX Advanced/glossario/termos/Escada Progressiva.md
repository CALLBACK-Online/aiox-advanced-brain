# Escada Progressiva

Modelo de evolução de uma solução: Script → Squad → Workflow → Runner → API → App → SaaS. Cada degrau acrescenta estrutura, repetibilidade ou produto somente quando a necessidade justificar.

## Como é usado

Use **Escada Progressiva** para escolher a menor superfície que resolve o problema agora e nomear o degrau atual com evidência verificável; a regra de ouro da aula: só sobe um degrau por vez, e só quando o degrau atual entediou de tão estável.

**Exemplo prático:** na aula [[69-escada-progressiva-script-a-saas]], o exercício é escrever uma linha "degrau atual · evidência · próximo · critério de subida": um relatório que hoje é Script só sobe ao degrau seguinte quando roda estável e repetido — e querer "SaaS essa semana" com uma landing page de pricing e zero automação estável é o anti-padrão do teleporte, que a aula manda redirecionar para o degrau real.

**Não confunda:** **Escada Progressiva** não é uma obrigação de chegar a SaaS nem uma escala de prestígio; é um freio contra o salto de degraus — cada degrau paga uma escola diferente (o Script ensina o procedimento, o SaaS ensina operação sob carga real), e pular os do meio só adia essa conta.
